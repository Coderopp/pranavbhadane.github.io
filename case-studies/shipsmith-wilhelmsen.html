Enterprise AI · Multimodal RAG

Building an Intent-Aware Multimodal RAG System for Maritime Engineering

Shipsmith × Wilhelmsen — a vessel-specific knowledge assistant that makes engineering documentation, diagrams and operational context accessible through natural-language queries.

Role: Product Manager & Forward-Deployed EngineerHybrid retrievalPostgreSQL + pgvector

01. The challenge

Maritime engineering teams work across equipment manuals, maintenance records, drawings and technical diagrams. Relevant answers can be distributed across text, structured metadata and visual references—making conventional document search too brittle for the workflow.

The objective was an AI knowledge assistant that could retrieve accurate, contextual information while adapting to team needs, query complexity and whether a visual reference was needed.

02. Intent-aware hybrid retrieval

An LLM-based intent router interprets each query before retrieval. It identifies relevant team context, topic-specific retrieval requirements, expected response length and whether diagrams or images should be included.

BM25 supports precise technical terminology while vector search supports contextual relevance. PostgreSQL holds embeddings, metadata and image references; image assets themselves remain in object storage.

03. Architecture exploration

ColPali-powered multimodal RAG

Visual page representations made this approach promising for diagrams, tables and complex technical documents.

  • Direct visual document retrieval
  • Text–diagram context preservation
  • Accuracy, latency and cost evaluation

Hybrid SQL-powered retrieval

PostgreSQL with pgvector combined lexical and semantic retrieval with structured-data control.

  • BM25 for terms and keywords
  • Vector similarity for semantic relevance
  • SQL-native metadata and image references

05. Evaluation and optimization

I implemented an evaluation framework tailored to teams and query categories, then used it to investigate each architecture's strengths and constraints.

Retrieval quality

Recall@K, Precision@K, MRR and NDCG measured retrieval and ranking quality.

Answer quality

Human evaluation, groundedness and answer correctness tested whether responses were useful and supported by context.

Operational economics

End-to-end latency and cost per query made system constraints explicit.

Optimization focus

Hybrid retrieval, query execution, context selection and token use were tuned without compromising the quality bar.

06. Productization

The resulting architecture became the foundation for a vessel-specific assistant: document ingestion, hybrid retrieval, textual and visual context assembly, intent-aware routing, contextual generation and voice-based interactions were designed around engineering workflows.

The core learning: enterprise AI architecture is a product decision. The useful system is not necessarily the most sophisticated model—it is the one that balances user requirements, retrieval quality, operational constraints and cost.
